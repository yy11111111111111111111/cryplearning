# AI 协作协议 v1

## 权责

| 角色 | 主责 | 不可代替的证据边界 |
|---|---|---|
| 用户 | 确定目标、作答、决定是否采用路线与规则 | 真实作答以用户原文或照片为准 |
| ChatGPT | 教学、当前局部路线、学习状态判断、错因反馈 | 根据本轮实际作答判断；给出证据与不确定处 |
| Codex | 出题、题库维护、全局路线设计、训练闭环与队列建议 | 题目须审查；不能仅凭生成或解题自检宣称适合投放 |
| Claude Code | 仓库工程、文件组织、元数据、脚本与自动化、按协议落盘 | 工程成功不等于用户收到题目、完成作答或掌握 |

同一文件同时需要两方修改时由交接单指定当前负责人。分歧保留两方主张、对应原文或作答证据、待裁决动作；AI 之间一致不替代事实核验或用户决定。

## 一次学习回合

1. ChatGPT 按用户请求选择讲解或闭卷检索。新对象先讲必要定义、来源、用途与转换条件；已有可调用知识才独立检索。
2. 投放前读取题面可见性状态。独立测量时只给学生题面，不给内部标签、答案、提示或类似题解。
3. 用户复述、推导或作答后，先忠实定位实际命题；如有错，找第一处独立实质断点。若缺前置，立即局部教学；若用户要直接解释，就直接解释。
4. 记录原始作答、题面版本、此前可见材料、反馈与独立性。即时修复后做一个改变关键条件的近迁移；适合时后续间隔检索。
5. Codex依据事件调整题库与全局路线；Claude Code只按已确认的字段和规则更新视图或自动化。

## 交接与版本

每次交接都写：任务与范围、base commit/文件版本、所见来源、用户可见内容、题目 ID、事件 ID、当前结论及证据、未决分歧、下一负责方和允许编辑文件。空白字段写`未核验`，不猜。仓库更新后，活动中的聊天会话仍须显式加载相应版本；GitHub 提交不等于自动同步给另一位 AI。

## 冲突处理

题面歧义、错误答案、缺条件、先前泄露、来源冲突或状态证据不足时，暂停该题的独立测量与能力晋级。能确定的事件仍如实追加；待审查修复后另开版本，旧题面与旧曝光关系不能抹掉。修改协议须标版本和理由，不回写篡改历史事件。
