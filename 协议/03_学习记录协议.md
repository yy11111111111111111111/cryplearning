# 学习记录协议 v1

## 事件优先

`学习记录/事件.csv`是可追加的事实流水。每行一个事件，至少包含：`event_id,occurred_at,recorded_at,item_id,item_version,concept_id,event_type,independence,source_ref,raw_ref,summary,actor`。时间采用含时区 ISO 8601；未知留空，不反推。`source_ref`指聊天、照片、文件或投放链接；`raw_ref`指原始作答文件。隐私敏感材料不上传公开仓库，可记录受限位置与摘要。

事件类型：`exposure`（题面/答案/决定性提示被展示）、`attempt`（用户实际作答）、`feedback`（纠正或教学）、`transfer`（关键条件变化的题及作答）、`delayed_retrieval`（间隔后检索及作答）、`void`（题目作废）、`correction`（更正一条旧记录）。`independence`取 `independent / cued / exposed_answer / unknown / not_applicable`。原始事件不覆盖；更正事件指出被更正的 event_id、理由与证据。

## 作答记录

保留用户原话、符号与草稿顺序，辨认不清处标`不清楚`，不能补写成标准答案。评语记录题目版本、当时可见内容、用户结论与关键依据、第一处独立实质断点、其他独立错误、反馈方式、即时修复结果、条件变化与下一复习建议。AI 造成的错误要明确归因，不记成学习者错误。

## 状态与掌握

状态是从事件推导的视图，不是新的事实。`unseen`仅在完整曝光登记覆盖该题全部投放渠道时成立；否则用`unknown`。即时答对、提示后复述、计划到期、提醒发送、文件提交都不能写作长期掌握。`mastery`如需单列，只写`未判定 / 有即时独立证据 / 有迁移证据 / 有延迟调用证据 / 需重新核验`及支撑的 event_id，不写单一永久“已掌握”。

## Error Log

只记录复发、高信心错误、稳定错误模型、同一规则致多错或高成本错误。每条标证据事件、第一断点、修复与复查结果；一次性笔误、OCR 问题、连锁后果或 AI 错误不自动入库。
