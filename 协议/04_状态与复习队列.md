# 状态与复习队列规则 v1

## 题目可见性与作答状态

| 状态 | 最低证据 | 解释 |
|---|---|---|
| `unseen` | 完整登记范围内，无该题及决定性等价内容的曝光事件 | 仅在曝光渠道清单完整时可用 |
| `exposed_only` | 题面、答案或决定性提示已见；无实际作答 | 不能当独立冷启动题 |
| `attempted` | 有用户真实作答；尚无合格独立正确证据 | 错、部分对、提示后对或未评定都可落此状态 |
| `independent_correct` | 无决定性提示的作答，结论和关键依据均成立，题目有效 | 仅支持该次即时表现 |
| `transfer_passed` | 独立完成改变关键条件、具有判别力的有效题 | 记录原题与迁移题的关系及证据 |
| `delayed_retrieval_passed` | 与上次决定性曝光隔开一段实际记录的时间，未先看答案，独立恢复核心结构与条件 | 记录实际间隔；不设固定天数门槛 |

保留各次事件与证据标志，不把六项当作不可逆等级。展示用主状态可按上表从下往上选最高有证据项，同时另列独立正确、迁移、延迟三项布尔/证据 ID。后续失败追加事件并标`需重新核验`，不删此前通过记录。题面泄露答案时，相关作答只算 `attempted`，不晋级独立正确；同机制变体也要评估曝光影响。

## Review queue

队列每行至少有 `queue_id,concept_id,item_id,reason,source_event_id,created_at,due_at,priority,status,last_result_event_id`。`due_at`为空代表待安排，不代表已到期。状态取 `pending / delivered / awaiting_answer / completed / cancelled`；提醒发出仅到 `delivered`，用户收到不自动推断。一次未答的投放维持 `awaiting_answer`，不要不断加发近似题。

排队顺序：先处理已交但未批改的答案；再处理已投放待答题；之后看已到期且依赖满足的项目。优先级来自当前断点、遗忘风险与路线依赖，不靠固定 D1/D3/D7 机械生成。轻松且依据完整可拉长间隔；犹豫正确可维持；再次串位或条件错误则缩短并做最小辨析；线索仍无效时局部重学。每次改期记录理由和来源事件。

队列只安排下一次有效行动，不等于已执行。自动化可提醒到期项，但不得替用户作答、把通知当送达、把无回复当失败，或自动升级 mastery。出现题目质量问题时暂停队列中的该题并保留原因。
