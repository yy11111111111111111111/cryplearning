# 题库协议 v1

## 题目生命周期

草稿 → Structural Validation（结构审查）→ Assignment Fit（当前投放适配）→ 可投放 → 已曝光/作答/封存。任何审查失败返回草稿或作废；修订题面须升版本，例如 `Q-...@v2`。先前版本的曝光不因修订自动清零；是否构成新独立题须看答案与决定性机制是否已泄露。

结构审查检查：定义与条件是否足够、目标是否明确、是否与所要求的唯一性一致、答案及推理是否正确、合法的不同解法是否被接受、有无反例或同样答案的错误模型。涉及安全结论时写清攻击者能力、资源、随机性与协议版本。审查记录和标准答案放教师私有处。

投放适配检查：目标知识是否已编码，是否暗含未学工具，难度是否来自提取、表示或条件判断，题面是否泄露决定性机制，是否与已曝光题近乎相同。用户要求练习时默认一题一轮；指定题组时遵从用户要求。只换数字或背景可练程序熟练度，不记作迁移。

## 题型与证据目标

可用闭卷结构检索、对象关系、过程重建、单条件近迁移、攻击构造、相似概念辨析、综合选择。每题内部记录目标、前置、判别性、标准答案与常见错误模型；这些标签不随学生题面投放。攻击构造题应明确已知、未知、可做的操作和目标。近迁移必须改变影响机制、结论、适用性或方法选择的一个关键条件。

## ID 与投放

题目 ID 固定，题面每次实质修改升版本。投放事件记录准确 ID、版本、完整题面快照或其内容哈希、投放时间、渠道和用户此前是否看过答案/提示。题面可推导出答案是正常的；问题在于直接写出待检验结论或决定性机制。先审查，后投放；题库中出现不代表已投放。
