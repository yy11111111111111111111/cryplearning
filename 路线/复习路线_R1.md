# 密码学复习路线 R1｜给教学 GPT 的规划

版本：2026-09-20 / R1。性质：用户要求 Codex 制定的复习建议，供教学 GPT 接手；尚未执行，不代表用户已逐阶段采纳或完成。依据是两份[历史基线](../学习记录/历史基线/README.md)与当前对话中用户希望开始复习的请求。历史报告尚未逐项核验。

## 为什么这样排

前三个月已经有学习和作答经历，当前主要缺少可追溯的调用证据。先从有较多历史线索、便于小范围检索的 Ch7 开始，再串起 Ch11 → Ch12 → Ch13，可以沿着已接触的内容检查对象、条件和安全目标是否清楚。其余模块分轮覆盖，不因第一轮未选中就被遗忘，也不因元数据不足要求整章重学。

这是一条复习线，和原有全书学习路线并行。两份旧报告的 CFB 与 Ch13 各自属于不同对话；本次选择 Ch7 作为复习入口是新的规划建议，不是裁定用户的全局学习进度退回 Ch7。新授会话仍按用户当下选择的节点继续。

## 阶段与调整依据

| 阶段 | 覆盖范围与顺序 | 目的与推进依据 |
|---|---|---|
| A：工作模式 | Ch7 核心模式；先从用户确认学过的一个模式做短检索，再逐步覆盖 CBC、CTR、OFB、CFB 与 ECB；XTS/FPE 留作后续适用范围复习 | 获取第一批真实记录，检查单个流程与条件。首轮不混考全部模式；流程可恢复后再安排比较和单条件变化 |
| B：Hash | Ch11 的接口、安全目标与使用条件 → 学过的结构 → SHA-2/SHA-3 局部过程 | 从目标与对象开始，按表现选择局部结构；不先要求完整轮常数或整套手算。原理层可调用后，再看实现细节 |
| C：MAC 与认证加密 | Ch12 的接口、密钥角色与目标 → 已学 MAC 构造 → AE 的保护范围与接口；CCM/GCM 等根据实际教学程度处理 | 连接前两阶段。只讲到概念层的内容先补必要教学，不直接测完整算法；旧报告中的断点只供选择复查范围，不能预判本次仍错 |
| D：数字签名 | Ch13 的签验接口与安全目标 → 选择一个已教过的方案恢复 → 再扩展到其他方案 | 不同时测完所有方案。每次进入具体算法前检查 RSA 或群/ECC 的必要依赖；缺哪部分补哪部分。未教过的算法、验证流程或攻击分类按新授处理 |
| E：公钥基础专门回访 | Ch9 RSA → Ch10 DH/ECC；ElGamal 按已学范围接入 | 系统补足此前只局部调用的内容。把过程恢复、正确性条件和安全条件分开检查；Ch10 曾暂停，不能把未学部分包装成复习 |
| F：对称原语、随机性与攻击 | DES/Feistel 与 AES 的必要结构 → Ch7 多重加密与攻击模型 → Ch8 随机生成与流密码；代数前置穿插补足 | 避免旧基础长期漏掉。攻击复习核对具体对象和资源条件；历史摘要中的攻击命名与推导不能直接当标准答案 |
| G：交错与应用连接 | 在有局部独立证据后，跨模块安排选择与条件判断；TLS/PKI 等只按用户实际学过的范围接入 | 检查能否在不同情境中选择并解释。未学应用仍是新授；协议版本需实际查来源，不用旧摘要代替 |

安全概念、古典密码、群/环/域不单独设置整章前置考试。在对应阶段需要时回访；若持续出现广泛缺口，再建议一个范围明确的专门模块。D 阶段若需要，允许提前插入 E 的局部内容；这不等于先把 E 整章验收完。

## 第一段怎样启动

首次复习的任务是建立一条可靠记录，不是宣布某章通过。默认从已学习的 CBC 单一流程开始；若用户本次明确要接续 CFB 或 Ch13，则尊重该请求，记录复习起点变化与原因，不强制折返。

开始前只确认本轮范围和作答条件，不先展示知识点大全、例题答案或具体解法。正式题由 Codex 另行生成、结构审查和投放适配；本文件没有附题，也不是可投放证明。教学 GPT 可先读取计划、恢复上下文，等有已审查题面后再开始正式检索。

首个有效作答后按证据分流：

- 无决定性提示且结论、依据和条件成立：记录该次独立表现，按需要安排一个有效近迁移，或继续下一局部并将此点留待间隔回访。
- 局部错误但已有方法：先忠实定位第一处独立断点，按用户要求给予重试或最小提示，避免一次讲完整章。
- 缺定义、表示或程序：直接补必要内容或完整范例，再逐步撤去支架；修复后的当场恢复单独标明提示关系。
- 题目本身不合法、含未建立前置、图片不清或答案有争议：先核验题目和材料；不据此评价用户能力。

旧题面曝光史不明时，独立性保留为未知；可靠旧证据后来补齐时可以重判。学习过知识本身不妨碍以后独立检索；重点是该次作答是否依赖答案、范例或决定性提示，以及距离上次相关曝光的实际间隔。

## 一次会话和阶段推进

建议一次约 20–30 分钟，作为可调整的工作量上限，不是有效学习的固定时长。默认一次一题，要求结论与关键依据；先处理未反馈的作答，再看待答项，之后才开新项目。有修复需要时，本次完成一个局部即可，不为完成流程追加整组题。

后续会话可先回访一个此前修复过且适合间隔检索的点，再继续本阶段；没有到期项就直接推进。间隔按实际表现和用户时间安排，不设置不可调整的天数。轻松正确可以拉长，犹豫正确可保持，再次串位则缩短并局部修复。

“可以进入下一模块”与“已经稳定掌握整章”分开。能无决定性提示恢复当前关键结构、说明所需条件，且不存在阻断下一模块的依赖缺口时，可推进并保留待复查点。迁移与延迟调用各自取证；不要求所有细节先达到最高状态。每完成一小段或发现跨模块依赖问题，ChatGPT 提交交接，Codex 再调整全局排序。

## 本次规划不生成学习事实

路线范围属于公开安排，不含具体题目答案、评分点或内部错因。当前事件表、状态表、复习队列仍无实际学习行；不把 A–G 阶段或计划日期直接写成已发生事件。以后由真实作答驱动状态和下次安排，不能因为这份路线已经推送就称复习已开始。

## 各方接手

ChatGPT 负责具体回合的教学、局部调整、作答判断与反馈；记录对话来源、时间、题目版本、用户原话、提示情况、第一断点、修复与后续实际表现。不能访问所需原文或文件时明确缺件。

Codex 负责正式题目的生成与审查、题库维护、跨模块路线与复习建议；收到回合记录后再决定全局调整。Claude Code 负责按协议落盘、文件组织和必要工程检查，不把存储成功当学习验收。

当前交付是路线与交接，未委派新任务、投放题目或启动自动提醒。用户可将[教学 GPT 接手说明](../交接/R1_复习路线给教学GPT.md)交给正在使用的教学对话；该对话实际读取并回执后，才算完成接手。
